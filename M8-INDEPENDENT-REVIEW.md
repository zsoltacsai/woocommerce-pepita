## How to reproduce

All commands run from the repository root. The integration stack is disposable
and uses only the test credentials in `integration/.env.example`; it never
contacts Pepita or a production store.

**Unit suite (133 cases, no WordPress required):**

```bash
php tests/run.php
# expected: 133 passed, 0 failed, 0 skipped
```

**Security-relevant API cases (11 cases):**

```bash
php tests/run.php api
```

**HPOS integration cases (60 cases):**

```bash
integration/scripts/setup.sh
docker compose --env-file integration/.env -f integration/docker-compose.yml exec -T \
  -e WPS_IT_SITE_URL=http://wordpress-hpos cli-hpos \
  wp --path=/var/www/html eval-file /integration/tests/seed.php
docker compose --env-file integration/.env -f integration/docker-compose.yml exec -T \
  -e WPS_IT_BASE_URL=http://wordpress-hpos -e WPS_IT_EXPECT_HPOS=yes cli-hpos \
  wp --path=/var/www/html eval-file /integration/tests/run.php
```

**Legacy storage integration cases (60 cases):**

```bash
docker compose --env-file integration/.env -f integration/docker-compose.yml exec -T \
  -e WPS_IT_SITE_URL=http://wordpress-legacy cli-legacy \
  wp --path=/var/www/html eval-file /integration/tests/seed.php
docker compose --env-file integration/.env -f integration/docker-compose.yml exec -T \
  -e WPS_IT_BASE_URL=http://wordpress-legacy -e WPS_IT_EXPECT_HPOS=no cli-legacy \
  wp --path=/var/www/html eval-file /integration/tests/run.php
```

**Both stores in one run (re-seeds each store first):**

```bash
integration/scripts/run.sh
```

The suite includes the feed HTTP cases (`Feed HTTP delivery`) and the order REST
route cases (`REST API`), which cover token authentication, ETag/304, API-key
handling, rate limiting and duplicate delivery.

**Evidence locations:**

- Local run logs: `integration/results/*.log`

- CI run logs and artifacts: the **Actions** tab of the repository; each

- CI job names: `lint (PHP 8.5)`, `unit (PHP 8.1)` … `unit (PHP 8.5)`,

## Known limitations and required staging checks

- The local suite proves the plugin against a real WordPress/WooCommerce/MySQL
  stack, including HPOS and legacy order storage, real HTTP/ETag/304 behaviour,
  Action Scheduler, WP-Cron, `dbDelta` and the REST order route. It does not prove
  Pepita's own acceptance of the feeds or its live order-forwarding behaviour.
- Pepita credentials and a seller staging account were not used. Manual staging must verify feed acceptance, product/category mapping, price and stock updates, and the seller's actual order-forwarding payload/response behavior.
- Manual staging must verify real shipping/payment mappings, label handling, order status transitions, retries, duplicate delivery, and operational logging without placing a customer order.
- The harness covers the plugin's behaviour with test-only credentials and
  fixtures. Production hosting details (page cache, object cache, proxy, TLS
  termination, real gateway IDs) still need a staging pass.
- No production readiness tag or release claim is made.
